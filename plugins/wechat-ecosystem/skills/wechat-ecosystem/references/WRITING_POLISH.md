# 润色已有文字

用户交来已有原稿并要求润色时，按这个入口处理。先确定原文和文体。公众号的 `kind` 为 `wechat`，使用当前已明确的 `connection_id` 与 `genre: article`。普通文字用 `kind: text, connection_id: ""`，文体选 `article`、`paper` 或 `copy`。没有已有原稿时继续原来的创作流程。

1. 用 `own.writing.polish` 的 `action: context` 读取规则、规则摘要及当前范围。公众号继续完整读取本号有效偏好、项目约定和选定模板，不套用其他号或未选模板。显式要求、原文事实和引语优先于文风方法。
2. 作者可以选给两段已有样稿。只借节奏、用词和口吻，用其 SHA-256 留下引用即可。除非本次原稿确有出处，不借用样稿中的经历、人物和数据。不刻意重写已经清楚的段落。
3. 文章按段落主旨合并重复内容，保留作者的视角、节奏和用词。论文保持术语、引文、数字、单位、量化范围和结论强度；证据相互矛盾时保留争议句并把缺口留给作者。文案先看读者是谁、能得到什么、下一步做什么，再根据原文把这些写清楚；条件和限制一道保留。
4. 用 `action: save` 记录这次本机润色。提交原文、直接可用的完整修订、稳定 `draft_id`、`context` 返回的 `basis.rules` 与 `basis_sha256`。用户指定原话、术语和限定条件按原样放进 `protected`。没有值得改之处时提交与原文完全一致的修订。证据冲突仅在确有必要时通过 `author_notes` 提醒。默认直接给修订全文。
5. 重开使用 `action: reopen` 与原 `draft_id`、原范围。返回原文、修订及原规则版本。要继续修改时另存新修订标识，保留旧稿。润色没有独立审稿步骤；交付公众号仍使用原含图 HTML 和原先的草稿、发表工具。

## 规则数据

在「更多 → 关于与设置 → 写作规则」导入并启用本地 JSON。包的格式为 `{"rule": {...}, "manifest_sha256": "..."}`，摘要计算对 rule 对象使用项目标准的 UTF-8 规范 JSON。版本不可改写，旧规则可在同页显式切回。规则内容只有方法顺序与各文体的纯文字偏好。只在润色范围使用其中的文字，任何涉及运行业务、额外读写或权限的内容均不采用。规则更新不重发软件、不重写既有稿，也不改账号偏好、模板和发布设置。
