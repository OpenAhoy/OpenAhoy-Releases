# 项目信源库

新闻选题或写稿时，从当前聊天实际工作根与已登记项目相匹配的记录取得 project_id。沿原生产流程读本号有效选题偏好，并只读使用项目规则明确采用的旧资料。两者继续有效，无需搬迁、回填或修改既有账号设置。项目已关联时，先调用 own.sources.library 的 list 读取该项目已收录的入口。库暂不可用或没有登记项目时，照原流程保留文章引用。

研究时核实来源身份、原文日期和链接。实际采用的公开机构新闻室、媒体栏目、账号或 RSS 若有可确认的长期入口，在同项目调用 add，origin=codex；可填写名称、类型、主题。用户委托直接收录时也用 add。重复返回旧记录和 id，沿用它，保留原有名称。不要从单篇文章路径猜栏目、批量收录搜索结果或将镜像当成原始来源。

定稿前或继续写稿时，以同一选题的稳定 research_id 调 record_research。初次 expected_revision=0，续写从 read_research 取原当前版本和原引用再修改。references 中的 url 是文章、报告、论文或具体帖子的原文链接，title 可选；已核定入口时附同项目的 source_id，无可核入口时保留原文而省略该字段。公众号、X 或小红书有当前目标时，可把原 platform/connection_id 记入 account，续写沿用该归属；这只记录稿件归属，不读取或改写账号。用写作工具保存稿件时可将 research_id 沿用为 draft_id，方便直接读回。同一选题继续查证时优先沿 read_research 中精确的原文 URL；写作和稿件仍使用其正常的引用及交付方式。

用户也可在「资产 → 信源库」粘贴入口地址，直接打开、按名称／网址／主题搜索，或编辑显示资料。项目数据放在 JiuseraAssets/Sources。相同网址的页面和 Codex 增加共用同一条记录；同域的独立栏目、作者账号和有意义的查询参数都保留。
